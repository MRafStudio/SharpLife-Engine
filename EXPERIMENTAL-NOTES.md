ВНИМАНИЕ: правки в этой ветке сделаны **исключительно для проверки**, можно ли вообще
оживить этот движок и заставить героя ходить по картам Half-Life.

Это **не** готовая реализация и **не** образец того, как надо писать код:

- решения принимались по принципу "лишь бы заработало", без анализа последствий;
- проверки узкие: гоняли в основном на c1a0 и по одной карте на главу;
- игровая логика (двери, монстры, триггеры, звук, сеть) не сделана;
- известна **утечка ресурсов**: спустя несколько часов работы движение героя начинает
  тормозить, а затем приложение наглухо зависает (скорее всего из-за постоянной
  перелинковки коллайдеров и роста списков сущностей в area nodes - см. ниже);
- код не ревьюился, тестов нет, комментарии местами описывают ход мысли, а не работу.

Цель ветки: проверить, решаем ли проект в принципе. Вывод - решаем.

## Проблема производительности (НАЙДЕНА И ИСПРАВЛЕНА)

Симптом (со слов Рафа): через несколько часов работы движение героя нещадно тормозит,
ещё через несколько часов приложение наглухо зависает.

Причина: `LinkEdict` добавлял коллайдер в список узла (Solids/Triggers), но не записывал
сам узел в `Collider.Area`. `UnlinkEdict` удаляет только из запомненного узла, поэтому
каждая перелинковка добавляла ещё одну копию. А `Transform.Origin` (getter) вызывает
`Collider.OriginChanged()` -> `LinkEdict` при КАЖДОМ чтении, и origin игрока читается
несколько раз за кадр. Список рос ~1600 записей в секунду (~5.7 млн за час), и каждая
трассировка перебирала весь этот мусор.

Замеры (c1a0, автопилот):
- до фикса: playerNodeSolids 26 -> 17480 за 20 секунд
- после фикса (`ent.Area = i;`): playerNodeSolids стоит на 11 при ~240 перелинковках в секунду

Правильная архитектура (как в GoldSrc): не перелинковывать на чтение, а двигать сущность
явным вызовом `SV_LinkEdict` при телепортации/движении. Текущее поведение "линковать при
чтении Origin" остаётся нездоровым, но хотя бы перестало течь.


## Что всё-таки проверено

- движок собирается на .NET SDK 9-10 (целевой рантайм - .NET Core 2.1 x86 через CORE_ROOT);
- c1a0, c1a1, c2a1, c2a2, c3a1, c4a1 грузятся без ошибок;
- игрок ходит, падает, стоит на полу, упирается в стены и brush-сущности;
- ворота func_door *30 на c1a0 держат: упор на x=344.03 при воротах на x=329
  (плюс 16 юнитов раздутия халла игрока).
